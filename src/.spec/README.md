This folder is the package-local Spec Led layer.

## Canonical Layout

- `README.md` (authored)
- `AGENTS.md` (authored, local operating guidance for agents working in this folder)
- `decisions/README.md` (authored ADR guidance for this workspace)
- `decisions/*.md` (authored durable cross-cutting ADRs)
- `specs/spec_system.spec.md` (authored, meta-spec for this folder)
- `specs/package.spec.md` (authored, package-level intent)
- `specs/*.spec.md` (authored subject specs)
- `state.json` (generated by `mix spec.index` and `mix spec.validate`)

## Agent WASM Source Mapping

The workspace contains one active subject for each of the 41 governing source
areas: `agent_wasm.specification_authority`,
`agent_wasm.conformance_vocabulary`, and the 39 numbered technical subjects
from profiles through production readiness.

Subjects are grouped by implementation layer:

- Protocol foundation: profiles, identities, artifacts, guest protocol, SDK, signals, actions, state operations, directives, and reducer.
- Runtime and durability: invocation, mailbox, registry, ingress, host flow, storage, atomic commit, effects, recovery, and crash acceptance.
- Security and coordination: threat model, capability policy, plugins, sandbox, provenance, agent graph, child lifecycle, delegation, topology, and topology recovery.
- AI and platform: model gateway, tool runtime, planning, context and control, workflows, host platform, developer toolchain, operations, and production readiness.

Every unimplemented subject uses an explicit `implementation_frontier`
exception. The exception is removed only when linked or executed proof exists.

## Core Loop

1. if you are entering the repo or handing work to an agent, run `mix spec.prime --base HEAD`
2. make the smallest code, docs, or test change that moves the behavior
3. add or tighten the smallest proof when behavior changed
4. run `mix spec.next`
5. if it says `needs subject updates`, update the right current-truth subject in `specs/`
6. if it says `needs decision update`, add or revise an ADR only when the change is cross-cutting and durable
7. when it says `ready for check`, run `mix spec.check --base ...`
8. use `mix spec.status` when you need coverage or frontier summaries
